# 2026-09-28 · 读书页热力图月份标签在手机宽度下与下一个月重叠

> 范围：`apps/site` —— 读书页热力图 `read-heatmap.vue`
> 类型：修复（布局缺陷）
> 状态：已修复（SFC 编译 + 无头 Chrome 复刻验证通过；未跑站点构建，见第 7 节）
> 影响：`/weread` 页面在 320–430px 视口下的月份标签行；跨年窗口受影响更明显

## 0. 摘要

热力图的月份标签把年份内联在文字里（`2026年4月`），文字宽约 55–62px，而标签实际可用的宽度只有「这个月跨了几列」（393px 视口下约 50px），溢出的部分直接压到下一个月的标签上。修复方式是把年份拆成标签**上方的一行 0.6rem 小字**：宽度需求从 55–62px 降到约 23px，而标签可用宽度最少也有约 40px，因此在任何手机宽度下都不可能再与相邻月份重叠，跨年窗口也能同时标出两个年份。

## 1. 现象

- iPhone 宽度（截图实测 393pt）下，热力图顶部 `2026年4月` 与 `5月` 叠在一起，同屏其它月份正常。
- 更宽一点看不出问题，更窄更明显：320px 视口重叠约 16px，375px 约 8px，430px 起才消失。
- 跨年窗口（参考月份为 1–5 月时会跨年）会**同时出现两处重叠**：`2025年10月` 压 `11月`、`2026年1月` 压 `2月`。
- 页面顶部的「数据统计自 微信读书 最后更新时间：2026-09-28」那一行是正常的，问题只在热力图的月份标签行。

## 2. 根因

月份标签行与热力图格子共用同一套网格列（`14px + repeat(N, 1fr)`、`columnGap: 3px`，见 `apps/site/src/features/weread/components/read-heatmap.vue:238`），每个标签用 `grid-column: start+2 / span span` 占位，`span` 就是该月跨过的周列数。问题出在“是否放得下”的判断方式：

- `minColsForLabel`（`read-heatmap.vue:140`）用**列数**估算（带年份 3 列、不带年份 2 列）；
- 但标签文字宽度是**固定像素**（`0.7rem` 下 `2026年4月` ≈ 55–62px），列宽却随视口变化；
- 两者量纲不同：393px 视口下 4 个列 ≈ 47–50px，本来就装不下 55–62px 的文字；
- 标签是 `whitespace-nowrap` 且不做裁剪，溢出部分因此直接压到下一列。

393px 恰好是两条保护同时失效的宽度：4 月的 `span = 4` 不小于阈值 3（跳过逻辑不触发），而估算又认为放得下（保守估算不触发），于是重叠就出现在常见的手机宽度上。

几何换算（`C` = 内容宽 = 视口宽 − 56，来自 `main` 的 `px-7`）：

```
网格盒子宽 = C + 17（标签行 marginLeft: -17px）
列宽 = (C + 3) / N − 3        // N = 周列数
相邻月份标签的起点间距 = 4~5 列 = 4×(列宽+3) ~ 5×(列宽+3)
```

| 视口宽 | 内容宽 | 列宽 | 相邻标签间距 | `2026年4月` 文字宽 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 320px | 264px | 6.88px | 39.5px | 55.3px | 与 `5月` 重叠 15.7px |
| 375px | 319px | 8.92px | 47.7px | 55.3px | 重叠 7.6px |
| 393px | 337px | 9.58px | 50.4px | 55.3px | 重叠 4.8px |
| 402px | 346px | 9.92px | 51.7px | 55.3px | 重叠 3.6px |
| 430px | 374px | 10.95px | 55.8px | 55.3px | 刚好不重叠 |

同一份页面在 iOS 上数字更宽：按用户截图逐像素量取，`2026年4月` 墨迹约 61px、`5月` 起点在 92px 处，重叠约 9px；要完全不重叠需要相邻标签间距 ≥ 61px，即视口 ≥ 约 465px——与“宽一点就没事”的观感一致。

跨年窗口（合成数据 2025-10 ~ 2026-03，25 个周列）现状：

| 视口宽 | 列宽 | 相邻标签间距 | 重叠 |
| --- | ---: | ---: | --- |
| 320px | 7.67px | 42.7px | `2025年10月`↔`11月` 19.1px、`2026年1月`↔`2月` 12.6px |
| 393px | 10.59px | 54.4px | 7.4px、0.8px |
| 402px | 10.95px | 55.8px | 6px、0（临界） |

测量方法：按组件结构（同列数、同 gap、同字号、同页面内边距）在无头 Chrome 中重建标签行，用 `Range.getBoundingClientRect()` 量文字墨迹，再逐对比较相邻标签的墨迹矩形是否相交。

## 3. 方案取舍

| 方案 | 思路 | 代价 | 结论 |
| --- | --- | --- | --- |
| A. 标签只留 `N月`，年份移到标题 | 宽度需求降到约 24px | 跨年窗口年份信息丢失，必须改标题行；320px 下标题行放不下区间，还要处理换行 | 未采用（可用作备选，需补标题改造） |
| B. 实测宽度 + 碰撞检测 | `ResizeObserver` 量容器宽 + canvas `measureText`，冲突就跳过或降级标签 | 引入运行时测量与 hydration 差异；窄屏会丢掉 `11月`/`2月` 整个标签 | 未采用（未来若必须恢复内联年份再用） |
| C. 给标签行加 `overflow: hidden` | 一行 CSS 止血 | 直接截断文字，信息损失更难看 | 否决 |
| **D. 年份改为标签上方的小字（采用）** | 年份独立成行，用 `items-end` 让月份贴同一底线 | 标签行高度 11.2px → 22.8px，热力图整体下移约 12px | **采用** |

选 D 的原因：年份小字只有 22.5–24.3px 宽，而标签可用宽度下限约 40px（320px 视口），**结构上**不可能再重叠；不需要运行时测量，也没有信息损失，跨年时两个年份（如 `2025` / `2026`）都能标出来。

## 4. 实施步骤

1. 模板（`read-heatmap.vue:235`–`255`）：标签行容器加 `items-end`；标签内部改为 `flex flex-col justify-end`，年份渲染成 `text-[0.6rem] leading-none opacity-85` 的独立一行，月份加 `mt-0.5 leading-none` 贴底。
2. 注释与含义同步（`read-heatmap.vue:135`–`148`）：`minColsForLabel` 的估算依据从“带年份更宽”改成“年份已不占月份行宽度”；说明跳过残片月时年份会顺延到下一个展示月份，最后一个标签不跳过。
3. 保留原有跳过规则（带年份至少 3 列、不带年份 2 列、末位标签不跳过）——年份拆行后该估算才真正成立（3 列 ≈ 29px ≥ 年份小字的 24.3px）。

## 5. 验证

- `@vue/compiler-sfc` 解析 + `compileScript` + `compileTemplate`：无错误；确认模板里已无内联年份写法。
- 无头 Chrome 复刻标签行（修复后的真实结构），覆盖 **320 / 393 / 402px × 跨年 / 同年** 共 6 组：

| 场景 | 结果 |
| --- | --- |
| 320px 跨年 | ✓ 无碰撞（年份小字 24.3px，标签间距 42.7px） |
| 320px 同年 | ✓ 无碰撞 |
| 393px 跨年 | ✓ 无碰撞（间距 54.4px） |
| 393px 同年 | ✓ 无碰撞（间距 50.4px） |
| 402px 跨年 / 同年 | ✓ 无碰撞（间距 55.8px） |

- 修复前后对比（393px）：跨年窗口由两处重叠变为 `2025` 浮在 `10月` 上方、`2026` 浮在 `1月` 上方，月份标签统一贴同一底线；同年窗口为 `2026` 浮在 `4月` 上方。
- 未覆盖：站点构建与真实浏览器水合（本机 `astro build`/`astro dev` 因 `astro sync` 的 `require is not defined` 报错无法运行，见第 7 节）。

## 6. 影响面与回滚

- 行为变化仅限 `/weread` 热力图标签行：标签行高度从 11.2px 变为 22.8px，热力图及其下方内容整体下移约 12px；月份标签的水平位置（与格子列对齐）不变。
- 不涉及数据、接口、构建产物与其它页面。
- 回滚：还原 `apps/site/src/features/weread/components/read-heatmap.vue` 一个文件即可。

## 7. 遗留 / 后续

- 本机 `astro build` / `astro dev` 会挂在 `astro sync`（`require is not defined`，picomatch 在 Vite SSR runner 里按 ESM 求值），因此本次只做了 SFC 级编译检查与结构级复刻验证，**上线前建议在可构建的环境跑一次 `pnpm build` 并肉眼确认手机宽度**。
- 边界情况：若参考月只有 1–2 个周列且需要显示年份（例如最新阅读日是 1 月 10 日），末位标签会保留年份，年份小字会向右溢出内容区约 16px（落在 `main` 的 `px-7` 内边距里，不会被 `overflow-hidden` 裁掉，也不与任何标签重叠）。若希望更保守，可在末位标签的 `span < 3` 时只保留月份。
- 如果以后想把年份改回内联（或加更多文字），必须先实现方案 B 的实测碰撞检测，否则会在同样的宽度区间复现本问题。
- 后续变更：热力图的标题行与「N 天 · 时长 …」的位置已在 [2026-09-28-heatmap-footer-summary.md](./2026-09-28-heatmap-footer-summary.md) 中调整（本次的月份标签行未受影响）。
