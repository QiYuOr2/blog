# 2026-09-28 · 热力图摘要移到底栏、移除标题行

> 范围：`apps/site` —— 读书页热力图 `read-heatmap.vue`
> 类型：调整（信息架构 / 布局）
> 状态：已修复（SFC 编译 + 无头 Chrome 验证通过）
> 影响：`/weread` 热力图的顶部标题行与底栏文案
> 关联：月份标签重叠修复见 [2026-09-28-heatmap-month-label-overlap.md](./2026-09-28-heatmap-month-label-overlap.md)（本次不改动月份标签行）

## 0. 摘要

去掉热力图顶部的「近半年阅读热力图」标题行，把原先在标题行右侧的汇总「N 天 · 时长 X 小时 Y 分钟」移到底栏左侧——也就是原先「点击某一天查看阅读时长」的位置。点击某一天仍然会显示当天日期与时长（其余格子压灰、选中格子描边），再点同一格回到汇总。热力图顶部因此少一行，整块内容更紧凑。

## 1. 调整前状态

- 顶部标题行：左「近半年阅读热力图」(`text-xs`)，右「N 天 · 时长 X 小时 Y 分钟」(captions 色)，行下 `mb-3`。
- 底栏左侧：「点击某一天查看阅读时长」提示文案；选中某天后变为「2026-09-28 · 24 分钟」。底栏右侧是图例「少 ▢▢▢▢▢ 多」。
- 用户诉求：汇总占在标题行右侧不划算，标题行本身可以去掉，汇总挪到底栏提示文案的位置；底栏的点击查看交互要保留。

## 2. 改动依据（空间预算）

底栏是 `flex items-center justify-between gap-2`，左侧 `truncate`（可收缩、超出显示省略号），右侧图例 `shrink-0`。所以左侧可用宽度 = 内容宽 − 图例宽 − 8px：

| 视口宽 | 内容宽（`main` 的 `px-7`） | 图例宽 | 左侧可用 | 汇总文字宽（Chrome） | iOS 截图实测 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 320px | 264px | 96.4px | 159.6px | 150.3px | ≈159px |
| 375px | 319px | 96.4px | 214.6px | 150.3px | ≈159px |
| 393px | 337px | 96.4px | 232.6px | 150.3px | 159px（截图量取） |
| 402px | 346px | 96.4px | 241.6px | 150.3px | ≈159px |

结论：375px 以上余量充足；320px 是唯一临界点（iOS 字体更宽，约剩 0～1px），见第 7 节。

<details>
<summary>为什么标题行右侧的宽度预算不是问题（改动前的对照）</summary>

改动前标题行是同宽度的 `justify-between`：标题「近半年阅读热力图」在 iOS 下墨迹 95px + 汇总 159px = 254px，对 320px 视口的 264px 内容宽只剩 10px。也就是说汇总留在标题行同样紧，移到只放图例的底栏后可用宽度反而更大（159.6px vs 约 100px），因此这次移动不会让文字更容易被截断。

</details>

## 3. 方案取舍

| 方案 | 思路 | 代价 | 结论 |
| --- | --- | --- | --- |
| A. 汇总移到底栏、删标题行 | 少一行、信息集中 | 失去「近半年」字样与标题；操作提示文案消失 | **采用** |
| B. 保留标题行，只把汇总移到底栏 | 保留标题 | 顶部仍有空行，收益减半 | 未采用 |
| C. 底栏同时显示汇总与提示文案 | 保留可发现性 | 320px 下必然截断，且两段信息语义重复 | 未采用 |
| D. 汇总留在标题行右侧，只删标题文字 | 改动最小 | 仍占一行，等于没做 | 未采用 |

## 4. 实施步骤

1. 删除模板中的标题行 `div`（改动前为 `read-heatmap.vue:227`–`233`，`mb-3 flex items-center justify-between` 那一块），热力图现在从月份标签行开始。
2. `selectedInfo` 重命名为 `footerText`（`read-heatmap.vue:210`–`218`）：未选中返回汇总 `${recentDayMap.size} 天 · 时长 ${totalDurationLabel}`，选中某天返回 `${key} · ${formatDuration(seconds)}`；取消选中的逻辑不变。
3. 底栏左侧 `{{ selectedInfo }}` 改为 `{{ footerText }}`（`read-heatmap.vue:291`，底栏 `flex items-center justify-between gap-2` 内的 `span.truncate`），`truncate` 保留。
4. 月份标签行、格子网格、图例、选中态样式均未改动。

## 5. 验证

- `@vue/compiler-sfc` 解析 + `compileScript` + `compileTemplate`：无错误；确认模板中已无「近半年阅读热力图」、底栏绑定 `footerText`，源码中已无 `selectedInfo` 与「点击某一天查看阅读时长」字样。
- 无头 Chrome 按改造后的完整结构渲染，覆盖 320 / 375 / 393 / 402px × 未选中 / 选中态：

| 场景 | 结果 |
| --- | --- |
| 320 / 375 / 393 / 402px · 未选中（汇总） | ✓ 完整显示（320px 下 Chrome 字体余量约 2.6px） |
| 320 / 375 / 393 / 402px · 选中 `2026-09-14` | ✓ 完整显示「2026-09-14 · 24 分钟」（110.4px） |
| 选中态交互 | ✓ 选中格描边、其余格压灰、底栏切换文案；再点同一格回到汇总 |

- 未覆盖：站点构建与真机水合（本机 `astro build`/`astro dev` 仍受 `astro sync` 的 `require is not defined` 阻塞，与上一条记录相同）。

## 6. 影响面与回滚

- 组件总高度减少约 28px（标题行 16px 行高 + `mb-3` 12px），热力图下方内容随之上移；月份标签与格子的位置不变。
- 底栏左侧文案变成两态：汇总（未选中）/ 当天信息（选中）；右侧图例不变。
- 页面不再显示「近半年阅读热力图」标题与「点击某一天查看阅读时长」提示；桌面端格子仍带原生 `title` 悬浮提示（`YYYY-MM-DD 阅读 X`），触屏端无额外提示。
- 回滚：还原 `apps/site/src/features/weread/components/read-heatmap.vue` 一个文件即可。

## 7. 遗留 / 后续

- 320px（iPhone 5s/SE 一代档）下底栏可用宽度与 iOS 字体的汇总文字几乎相等（约 0～1px 余量），极端情况下汇总可能被省略号截断。若在意，可把图例的 `gap-1`（4px）调成 `gap-0.5`（2px）释放约 12px，或把图例方块从 10px 缩到 9px。
- 「近半年」的时间范围只体现在月份标签上，标题删除后不再有文字说明窗口跨度；跨年时窗口范围由月份标签上方的年份小字表达。
- 操作提示文案移除后，热力图对触屏用户不再自带「可点击」的提示。若后续想补回，建议放在组件外层说明文案或格子的 `aria-label`，不要放回底栏（会与汇总争宽度）。
